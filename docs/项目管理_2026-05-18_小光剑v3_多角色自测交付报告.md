## 四、数据层根因（需 Jedi 决策）

### 4.1 Position.avg_cost 为什么错乱？

现有数据样本显示 `avg_cost` 与 `base_cost` 严重偏离：
- 美团：3388 vs 105（32 倍差距）
- 腾讯：405 vs 508（20% 差距）
- 特斯拉：353 vs 402（12% 差距）

**推测原因**：
1. 早期交易记录同步（sync_futu）时 avg_cost 被**富途 API 返回的某个字段覆盖**，而富途的成本口径（含现金/股票互换后的调整）和 Jedi 理解的成本口径（实际买入价）不一致
2. 或者历史批量数据导入时 avg_cost 字段被**手动录入错误**
3. 或者是**除权复权**导致成本调整（如送股拆股后成本被调整，但 base_cost 没同步）

**根因定位路径**（建议）：
- 查看 2026-04-03 前后 sync_futu 的日志（或 git blame）
- 对比富途 OpenD API 返回的原始 `avg_cost` 值和数据库中的值
- 判断是 API 问题还是录入问题

### 4.2 哪些持仓数据本身坏？

Jedi 需要手动核对的持仓：

| 股票 | 问题 | 建议 |
