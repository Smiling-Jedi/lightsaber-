# 待办事项

## 问题：服务层返回格式复杂导致数据解析困难

**发现时间**: 2026-03-27
**优先级**: 中
**标签**: 技术债务、代码优化

## 问题描述

在尝试通过 `PositionService` 获取总资产明细时，发现服务层返回的数据结构复杂且不一致：

1. **返回格式不统一**
   - `get_portfolio_summary()` 返回字典，但某些字段可能缺失（如 `total_value` KeyError）
   - `get_position_summary()` 返回字典，但某些值为 `None` 导致计算出错

2. **具体错误**
   ```python
   # KeyError: 'total_value'
   portfolio['total_value']

   # TypeError: unsupported operand type(s) for +=: 'float' and 'NoneType'
   total_market_value += market_value  # market_value 为 None
   ```

3. **字段映射问题**
   - 数据库模型 `Position` 没有 `current_price` 字段，价格需要从关联的 `Stock` 表获取
   - 盈亏计算逻辑分散在 service 层和模型 property 中，容易不一致

## 影响

- 无法直接通过脚本快速获取持仓数据
- 网页展示时可能有同样问题（但前端可能做了兼容处理）
- 数据核对困难

## 建议解决方案

1. **方案A：统一返回DTO**
   ```python
   class PositionSummaryDTO:
       symbol: str
       name: str
       shares: int
       avg_cost: float
       current_price: float
       market_value: float
       pnl: float
       pnl_percent: float
       # 所有字段都有默认值，不会为None
   ```

2. **方案B：添加防御性编程**
   - 所有 service 方法返回前确保数值字段不为 None
   - 使用 `float(value or 0)` 处理可能为 None 的值

3. **方案C：直接SQL查询**
   - 对于简单统计，绕过 service 层直接查询数据库
   - 适合脚本/后台任务使用
