## 三、核心反思与经验沉淀

### 3.1 「写文档」≠「真执行」
- ❌ 错误模式：把"扮演角色"理解成"写一份角色视角的文档"
- ✅ 正确模式："扮演测试工程师"= **真去打开页面、真去点按钮、真去对数据、真去找 Bug**
- ✅ 沉淀到本次自测：每个角色都要有可验证的产出（测试 = 真截图 + Bug 单；研发 = 真 diff + 真验证；分析师 = 真核对个股 + 真改进意见）

### 3.2 文档语义要分维度
- 持仓同步 / 价格更新 / 现金余额 是三个独立维度，CLAUDE.md 已明确规范
- 今日 A 股 K 线讨论时再次确认：**iFinD/Tushare 都不能做持仓同步，A 股持仓只能 Jedi 手动录入**
- 数据源优先级仅适用于"价格/历史/基本面"，不涉及"账户持仓"

### 3.3 部署链路的关键经验
- GitHub Pages 静态页对 Jekyll 处理默认敏感：必须 `.nojekyll` 关闭，否则下划线开头的目录/文件 404
- 仓库 public 但只发布"经过抽象的分析结果"，原始持仓数据**永远不上 Git**
- 一键部署脚本（`deploy_mini.sh`）需要包含：跑分析 → 生成静态 HTML → commit → push，避免 Jedi 手动操作
