## 一、T+1 限价单模式最终实现

### 1.1 核心设计确认

**背景**：模拟交易中的 SELL 信号需要实现 T+1 限价单模式，避免当天卖出后资金无法使用的问题。

**最终实现方案**：

| 组件 | 实现内容 |
|------|----------|
| `SellPlan` 模型 | `target_date` 字段记录计划执行日期 |
| `execute_sell_plan()` | 每日定时扫描，仅执行 `target_date <= today` 的计划 |
| 刷新逻辑 | 市价单：`signal_date = today`；限价单：`signal_date = today + 1天` |
| 执行检查 | `is_ready_to_execute()` 判断是否到达执行日期 |

### 1.2 关键代码位置

- `app/models/sell_plan.py` - 卖出计划模型
- `app/services/sell_plan_service.py` - 服务层实现
- `app/routers/sell_plan_router.py` - API 路由

### 1.3 模板页面

- `app/templates/sell_plan_list.html` - 计划列表
- `app/templates/sell_plan_form.html` - 创建/编辑计划
- `app/templates/sell_plan_detail.html` - 计划详情

## 二、SellPlanService 服务层补充

### 2.1 补充内容

补充了以下方法：

```python
# 获取待执行计划（target_date <= today 且状态为 PENDING）
get_pending_plans_due(db, date)

# 获取今日创建的计划
get_plans_by_signal_date(db, date)

# 获取持仓关联的所有活跃计划
get_active_plans_by_position(db, position_id)

# 批量取消计划
cancel_plans_by_position(db, position_id)

# 检查持仓是否有冲突计划
has_conflicting_plan(db, position_id, exclude_id)

# 获取计划执行历史
get_plan_execution_history(db, position_id)

# 计算建议卖出数量（用于表单预填充）
calculate_suggested_quantity(position)

# 验证卖出数量是否合法
validate_sell_quantity(position, quantity)
```

### 2.2 业务规则

1. **单一活跃计划**：一个持仓同一时刻只能有一个 PENDING 计划
2. **数量校验**：卖出数量 ≤ 当前可卖数量
3. **自动过期**：超过有效期未执行的计划自动转为 CANCELLED
4. **执行后状态流转**：PENDING → EXECUTED 或 FAILED

## 三、数据源优先级配置文档化

### 3.1 核心原则：维度分离

明确区分三个独立维度：

| 维度 | 港股 | 美股 | A股 |
|------|------|------|-----|
| **持仓同步** | 富途OpenD API | 富途OpenD API | ✗ 无API，手动录入 |
| **价格更新** | iFinD > OpenD > Tushare > Yahoo | iFinD > OpenD > Tushare > Yahoo | iFinD > Tushare > EastMoney |
| **现金余额** | OpenD API | OpenD API | 手动录入 |

### 3.2 避免的误区

**错误表述**（已修正）：
> ❌ "港/美股：富途OpenD API自动同步"
> ❌ "A股：Tushare > OpenD > Yahoo"

**问题**：将"持仓同步"与"价格数据源"混为一谈，暗示A股可以用OpenD同步持仓。

**正确表述**（已采用）：
> ✅ 明确标注每个维度是"自动"还是"手动"、"有API"还是"无API"
> ✅ A股持仓同步：✗ 无API支持，必须用户手动录入（截图/口头告知）
