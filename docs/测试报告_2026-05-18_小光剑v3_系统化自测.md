## 二、P0 致命 Bug — Position.avg_cost 数据层错乱（最关键）

### Bug-001 美团 03690 盈亏显示 -97.6%（应为 -21.3%）

**现场**：
- 首页/详情页显示：盈亏 -97.6%
- 底仓信息：200 @ 105.1
- 当前价：82.70

**真实计算**：
- (82.70 - 105.1) / 105.1 = **-21.3%**

**根因**（已定位）：
- 数据库 `Position.avg_cost = 3388.66`（远高于 base_cost 105.1）
- mini_router.py:204 用的是 `position.avg_cost`，没复算 base/swing 加权

**严重性**：误导用户认为美团巨亏，影响决策

### Bug-002 腾讯 00700 盈亏显示 +12.4%（应为 -10.2%）

**现场**：
- 底仓 6000@488.84 + 波段 1200@605.25
- 当前价 456.40
- 显示盈亏 +12.4%（错误方向，亏改成盈）

**真实计算**：
- 加权成本 = (488.84*6000 + 605.25*1200) / 7200 = **508.24**
- 盈亏 = (456.40 - 508.24) / 508.24 = **-10.2%**

**根因**：
- 数据库 `Position.avg_cost = 405.87`（与加权成本 508.24 严重偏差）
- 同样使用了错误的 avg_cost 字段

### Bug-003 建滔积层板 01888 成本为负数

**现场**：
- 数据库 `base_cost = -28.6420`
- 数据库 `avg_cost = -28.6420`
- 持仓 5000 股

**问题**：成本不可能为负，且若按 -28 算盈亏，会得到 +146% 这种荒谬数字（但页面显示 +0.0% — 说明前端做了边界保护，但根本没有触发预警）

### Bug-004 Lumentum LITE base_cost 为空但 avg_cost=936.82

**现场**：
- 数据库 `base_cost = None`
- 数据库 `avg_cost = 936.82`
- 持仓 1 股
- 当前价 979.37

**双重问题**：
1. 数据矛盾：base_cost 空但 avg_cost 有值
2. **当前价 979.37 本身可疑** — Lumentum 真实股价应在 60-130 美元区间，979 量级 K 线数据可能整条都是错的

### Bug-005 中信证券 600030 swing_shares = -3000

**现场**：
- base_shares = 3800
- swing_shares = **-3000**（负数）
- total_shares = 800
- avg_cost = 109.79

**问题**：
- swing_shares 负数语义是「卖空」？但 A 股账户不允许卖空
- 更可能是数据导入时出错（应该是减仓 3000 但被记成了 swing 负仓位）
- 显示盈亏 -76.0% 也很可能不对

## 三、P1 功能 Bug

### Bug-006 A 股板块出现港股代码，无明确标注

**现场**：
- A 股板块包含 09988 阿里、01810 小米
- Jedi 5-16 已说明：「这两个是 A 股账户买的港股通」

**问题**：
- 业务正确，但 UI 上没有标识「港股通」
- 容易让用户误以为分类错误
- 阿里在「港股板块」（6.5%仓位）和「A 股板块」（53.5%仓位）**同时显示**，但没有任何"两个账户分别持仓"的提示

### Bug-007 A 股仓位总和 231.8% > 100%

**仓位列表**：
- 阿里 53.5% / 比亚迪 26.0% / 阳光电源 12.4% / 宁德 7.6% / 中信 0.4%
- 小米 94.9% / 交行 1.8% / 兴业 1.8% / 招行 1.7%
- 医药ETF 17.0% / 机器人ETF 14.7%
- **合计 231.8%**

**根因**：
- `market_total_fund` 字段是单一值，无法区分「A 股账户的真 A 股资金」vs「A 股账户的港股通资金」
- 港股通持仓的市值（HKD）和真 A 股市值（CNY）被混算到同一个 `market_total_fund`（CNY）

### Bug-008 ETF 显示「— 暂无形态分析 —」

**现场**：
- 医药ETF易方达 512010、机器人ETF华夏 562500

**问题**：
- 不清楚是产品决策（ETF 不做形态分析）还是 Bug（数据没补齐）
- 若是产品决策，文案应改为「ETF 不参与形态分析」更明确
- 若是 Bug，应补跑 ETF 的形态分析

### Bug-009 LITE 当前价 979.37 异常

**现场**：
- 详情页"形态分析"段落里所有数字都是 600-1100 量级（颈线 1085.68 / 左肩 616.09 / 头部低点 558.44 等）
- 真实 Lumentum 股价应在 60-130 美元
- 整条 K 线数据看起来都是错的（不是单点错）

**推测**：
- 数据源串号（拉错代码）
- 或反向拆股后的复权问题

## 四、P2 体验 Bug

### Bug-010 favicon.ico 404
- Console 持续报 `Failed to load resource: 404 favicon.ico`
- 解决：加 docs/mini/favicon.ico 或 link 标签

### Bug-011 数据快照时间含义不清
- 首页右上角显示「05-18 11:28」，实际测试时已 12:38
- 用户会误以为是「数据更新时间」，实际是「快照生成时间」
- 应改为「数据快照：05-18 11:28」明确语义

### Bug-012 ⚠️ 高 风险标签触发不一致
- 微软 MSFT 共振看涨 ⭐⭐⭐⭐⭐ + 评分 🟡 6.0 — **无 ⚠️ 高**
- Lumentum LITE 共振看涨 ⭐⭐⭐⭐⭐ + 评分 🟡 6.3 — **有 ⚠️ 高**
- 同样的共振强度，但风险标签不一致，规则不明确

### Bug-013 共振描述过长（移动端）
- "日/周/月三周期同步看涨，短中长期资金达成共识，信号最强" 共 26 字
- 移动端窄屏会折成两到三行，造成视觉拥挤

### Bug-014 美股 +/-% 标的实际是上一交易日数据
- 周一上午 12:38 美股未开盘（北京时间 21:30 才开）
- 但页面美股段全部显示 -3.3% / -6.6% / -9.0% 这样的非零涨跌
- 实际是 05-15 周五收盘 vs 上一交易日的涨跌幅
- 文案易误导：用户以为是"今天的"美股涨跌

### Bug-015 阿里 09988 港股板块和 A 股板块同时显示，但同一只股票
- 港股板块：阿里 09988，盈亏 -0.4%，仓位 16.5%
- A 股板块：阿里 09988，盈亏 +15.1%，仓位 53.5%
- 两条记录的「同一股票符号」造成困惑（应区分 stock_account=HK 和 A）
